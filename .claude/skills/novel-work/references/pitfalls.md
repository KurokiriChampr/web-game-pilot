# 守ること・つまずきやすい所

## 作品の作り方

| こと | 理由・やり方 |
| --- | --- |
| エンジン（`index.html`・`js/`・`css/`・`tools/`）と本作のファイルを書き換えない | 本作の公開サイトと既存の検査が壊れる。作業の最後に `git status` で、変わったのが `works/<作品ID>/` だけか確かめる |
| エンジンに足りない機能が要るときは止めて知らせる | エンジンの変更は別の作業（本作の検査 7 本と保存キーの確認が要る） |
| 作品 ID は公開後に変えない | 保存キーの接頭辞なので、変えるとセーブ・既読・見た結末が引き継げない |
| 同じサイトに置く作品どうしで ID を重ねない | 同じドメインの localStorage を共有するので、セーブが混ざる。`new-work.js` はリポジトリ内の重複だけを弾く |
| シーン ID に `#` と `>` を使わない | 既読の記録（`シーン#指紋`・`シーン>指紋`）の区切り |
| 同じシーンに同じ本文のページを置かない | 既読がページの本文の指紋で記録されるので、2 ページが既読を共有する |
| 公開後に本文を直すと、そのページは未読に戻る | 既読は本文の指紋。誤字の修正でも既読スキップが止まる（害は無い） |
| 公開後に変数・人物を宣言から外すと、セーブの値は読み込み時に落ちる | 戻すと初期値から。外す前に依頼者に確かめる |
| 結末でないシーンは選択肢か `next` で終わる | 無いと先へ進めない（点検で誤り） |
| 立ち絵は 1 か所に 1 人・最大 3 人 | 人のいる位置に別の人を立たせると、先の人が退場する（点検で注意） |
| 関数（`text`・`next`・`requires`）は状態を読むだけ | 点検は関数を何度も呼んで試す。書き換えると点検と画面の結果がずれる |
| 章は `story.js` の中に書く | 章をファイルに分けると `index.html` の写しが要る（エンジンの複製になる） |
| `module.exports` の行を消さない | 点検ツールと足場スクリプトが Node で読むのに使う |

## 公開（`build-work.js`）で残る本作の部分

| 残るもの | 扱い |
| --- | --- |
| タイトル画面の紋章（`index.html` の文字盤の針）と演出 | 本作の絵のまま。外す・差し替えるのはエンジンの課題（汎用化報告書の見送り）。依頼者に伝える |
| 版（`data-app-version`・`?v=`・`js/game.js` の `VERSION`） | エンジンの版のまま（3 か所が一致しないとエンジンが古い画面と判断する）。作品ごとの版の付け方は未決 |
| `<meta name="theme-color">` | 本作の色のまま |
| 結末の種類ごとの飾り（`css/style.css` の絵文字） | 本作向け |
| 本作の素材を借りたもの | `build-work.js` が一覧で出す。公開する作品では、作品の `assets/` に自前の素材を置く |

- 出力フォルダはリポジトリの外に作る（リポジトリの中は拒む。写しを残すとエンジンが 2 か所になる）。
- エンジンを直したあとは、もう一度まとめ直す（出力は写しなので、自動では追随しない）。
- `index.html` をダブルクリックで開くと、ブラウザの制限で画像・BGM が出ない。確かめるときは `python3 -m http.server` などで配信する。
