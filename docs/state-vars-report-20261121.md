### 書き方（作品側）

```js
var STORY = {
  vars: {
    gold:  { initial: 100, min: 0 },
    trust: { initial: 0, min: 0, max: 10, per: ["aoi", "beni", "sui"] }
  },
  scenes: {
    market: {
      onEnter: { vars: { gold: 20 } },
      choices: [
        { text: "花を買う", next: "plaza",
          requires: function (s) { return s.vars.gold >= 30; },
          effects: { vars: { gold: -30, trust: { aoi: 1 } } } },
        { text: "指輪を買う", next: "plaza", effects: { vars: { gold: { set: 0 }, trust: { beni: 5 } } } }
      ]
    },
    plaza: { next: function (s) { return s.vars.trust.aoi >= 4 ? "end_aoi" : "end_alone"; } }
  }
};
```

## 2. 設計からの判断

1. **宣言から外れた変数は「落とす」にした（設計 §1-1 (e) の表は「消さずに残す」）。** 今回の指示「宣言から外れた変数は落とす」に従った。設計が「残す」としていた理由は「古い版の画面に戻ったときに値を失わないため」で、これは変数を宣言した別作品が、版の更新で変数を消したあと古い画面へ戻る場合にだけ関わる（本作は変数を宣言しないので影響なし）。人物ごとの変数で `per` から外れた人物も、同じく落とす。
2. **宣言の無い作品でも、セーブに `vars` があれば落とす。** 「宣言の無い作品ではセーブに vars を書かない」を、読み込み時にも保証するため。本作のセーブに `vars` が入る経路は無いので、実際には起きない。
3. **`snapshotOf` は `create` の外に残した。** B の報告書 §5 では「`vars` の宣言を読む必要が出たら `create` の中へ移す」としていたが、「状態に `vars` があるときだけ写す」で足りたので、宣言を読まずに済んだ（API の形も B のまま）。
4. **「控えに `vars` の無い行には戻るを出さない」ために `canRewindFrom` を足し、`game.js` の 1 行を差し替えた。** 設計 §1-1 (e) の例外の記述どおり。`isValidSave` 自体は変えていない（セーブとしては有効なまま）。
5. **初期値が範囲外の宣言**：エンジンは範囲へ収めて使い、点検ツールは誤りにした（書いた人の意図と違う値で始まるため）。
6. **人物ごとの変数に `{ set: 値 }` を直接書いた場合**（`trust: { set: 3 }`）：設計どおり「`per` があるかで決める」ので、`set` を人物 ID として扱い、`per` に無いので無視・警告。点検では「人物ごとの変数の更新は { 人物 ID: … } の形に」という誤りにした。
7. **点検で変数を振る値**：設計は「下限・初期値・上限。幅が 20 以下なら全部の整数」。制限の無い変数（`gold` のように上限なし）だと「上限」が決まらないので、「**初期値の前後 20 までの整数と、下限・上限**」にした（幅 20 以下の変数では設計と同じく全部の整数）。振るときはフラグの組合せ（全部なし／全部あり／1 つずつ）と掛け合わせ、好感度・欠片は 0。
8. **`affection`・`shards` は変数に含めていない**（設計どおり、既存の挙動は不変）。
9. 点検の「誤り／注意」の分け方は設計 §1-1 (b)(c) と §1-3 の表どおり。設計の表にある「`WORK.hud.items` が未宣言の変数を指す」「5 個以上で注意」は HUD を入れていないので、点検も入れていない。

## 5. 判断に迷った点

1. **宣言から外れた変数を落とすか残すか**（§2-1）。指示に従って「落とす」にしたが、設計書は理由を付けて「残す」としていた。違いが出るのは「変数を宣言した別作品が、版の更新で変数を消し、そのあと利用者の端末で古い版の画面が開いた」ときだけ（古い版では、消えた変数が初期値からになる）。本作には関係しない。設計書の側を直すか、このままでよいか、確認をお願いしたい。
2. **点検で振る値の範囲**（§2-7）。上限・下限の無い変数で「初期値の前後 20」にしたのは私の判断。大きな数（所持金 1000 で判定など）を使う作品では、閾値が試す範囲から外れて「たどり着けません」の注意が出うる（誤りではなく注意なので、作品は動く）。
3. **当てられない更新を、エンジンで警告だけにしたこと**は設計どおりだが、点検ツールは誤りにしている。点検を通した作品なら実行時の警告は出ない前提。
