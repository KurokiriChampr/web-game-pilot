## 1. 採用した改善（GUI／機能）と、その理由

### A. 読み返し・やり直しの導線

| 内容 | 理由・補足 |
| --- | --- |
| バックログは「読んだページまで」だけを表示 | 4 / 5 ページ目を読んでいる途中で 5 ページ目が読めてしまう不具合の是正。保存形式は変えず、表示の側で絞った（保存されるログは従来どおり全段落） |
| バックログの選択肢の行に「この選択肢に戻る」 | **判断 1 のとおり、いずれかの結末を 1 つ見るまで出さない。** 判定は既存の `chrono-tale-endings-v1` を読み、シナリオに実在する結末 ID が 1 つ以上あるかで決める。押すと確認を出し、その選択の直前（そのシーンの最終ページ＋選択肢）へ戻す |
| 結末画面に「最後の選択肢からやり直す」 | 到達した画面から使うものなので、解放条件なしで使える。確認は出さない（失うものが無いため）。見た結末の記録は残る |
| 状態の控え | 選んだ時点の状態（シーン・好感度・欠片・フラグ・幕数）を、バックログの選択肢の行に `s` として持たせた。セーブデータ最上位の形は変えていない。控えの無い行（旧版で選んだ行）には「戻る」を出さない |

### B. 下部クイックバーと操作の整理

| 内容 | 理由・補足 |
| --- | --- |

| オートモード | 文字送り完了後、`基本の待ち＋文字数×係数` で次ページへ。速度は 3 段階（ゆっくり／ふつう／はやい、設定に保存）。A キーでも切り替えられる。止まり方は §3-1 を参照 |

### C. 既読をページ単位に

| 内容 | 理由・補足 |
| --- | --- |
| 既読を「シーン ID＋段落本文の指紋」で記録 | **判断 2 のとおり、キー名は変えず `chrono-tale-read-v1` の配列に別形式で追記。** `meet`（従来のシーン ID）、`meet#指紋`（読んだページ）、`meet>指紋`（選んだ選択肢）。指紋は FNV-1a 32bit の 36 進で、本文そのものは保存しない |

## 3. 判断に迷った点

1. **オートが「止まる」の解釈。** 指示は「選択肢・ダイアログ表示・タブ非表示で止まる」。次のように分けた。
   - 選択肢：進行が止まる（自動では選ばない）。オートの状態は保ち、選んだあと次のシーンで再開する。
   - ダイアログ表示・タブ非表示：オートを解除する。閉じたり戻ったりしても勝手には再開しない。
   - 理由：本作は 1 シーン 3〜7 ページで必ず選択肢に当たるので、選択肢でも解除にすると毎シーン押し直しになり、オートの意味がほぼ無くなる。3 つとも「解除」が意図であれば、`endOfScene` の 1 行で切り替えられる。
2. **旧データ（シーン単位の既読）の引き継ぎ。** 旧版の記録からは「どの段落を読んだか」が分からない。旧版で読んだシーンは、新版で最初に入ったときの段落構成を既読として引き継ぐことにした（従来のシーン単位スキップと同じ扱い）。その 1 回だけ、周回で初めて出る段落が既読扱いになりうる。以後はページ単位で正しく記録される。逆に全部未読へ戻す案は、読んだはずのシーンでスキップできなくなるので採らなかった。
3. **スキップボタンは隠さず「押せない」表示にした。** 調査報告は「既読ページがあるときだけ出す」だが、5 つ並びのクイックバーで 1 つ消えると位置がずれて押し間違いのもとになる。未読ページの上では薄くして押せなくした。
4. **タイトルの紋章の ⏳ を文字盤の針（SVG）に置き換えた。** F-4 の「針を動かす」には針が要るが、従来の紋章には目盛りの輪と砂時計の絵文字しか無かった。ふだんは 10 時 8 分で止まった針、4 結末のあとは動く針にした。**初回から見えるタイトルの見た目が少し変わる**（回転する砂時計が無くなる）点は、指示の外の変更なので明記する。
5. **既存テストの期待値の書き換え。** 「検証を弱めない」との指示に対し、次の 4 か所は仕様変更に合わせて書き換えた。いずれも確認の数は増やしている。
   - 旧バックログの段落数：従来は「全段落が出る」を確認していた（＝今回直した不具合の挙動）。「読んでいる途中は読んだページまで／読み終えると全段落／保存データは旧データのまま」の 3 点に置き換えた。
   - バックログの話者名：同じ理由で、途中と読了後の 2 回確認する形にした。
   - 「スキップが出る」→「スキップを押せる」（上の 3 のため）。
   - 確認ダイアログ：ブラウザ標準の `confirm` を自動で承認していた箇所を、自前のモーダルの「はい」を押す形にした。
6. **`tools/e2e.js` の土台の直し方。** 失敗の原因は「立ち絵ファイル 0 個」「18 シーンは従来形式」という Phase 1 時点の前提だった。実素材を消すわけにいかないので、プレビュー用サーバに「指定したフォルダを無いことにする」オプション（`hide`）を足し、素材なしの検査を続けられるようにした。従来形式のシーンはシナリオに残っていないため、その 2 件は新形式での期待値に置き換えた（従来形式の計算は `tools/test-stage.js` が引き続き見ている）。背景焦点の検査は、実素材ありと素材なしの両方を見るように増やした。
7. **「この選択肢に戻る」の解放の瞬間。** 既存の実装は、結末シーンに入った時点で結末を記録する。そのため、初めての結末の本文を読んでいる最中にバックログを開くと、もう「戻る」が出ている。「既存の結末データに基づく」との指示に従い、記録のタイミングは変えていない。
8. **マウスでクイックバーを押したあとのフォーカス。** ボタンにフォーカスが残ると、続けて押した Enter が「読み進め」ではなく「ボタンの押し直し」になる（検査中に見つけた）。マウス・タップで押したときだけ、フォーカスをメッセージウィンドウへ戻すようにした。キーボードで押したときは動かさない。
9. **文字「特大」での選択肢。** 360×640 で選択肢が 4 個の場面（boss）は、特大だと 31px はみ出し、選択肢の枠の中でスクロールになる。標準では全部が 1 画面に収まる。特大は利用者が選んだ結果なので許容した。

## 4. 未解決

1. **実機未確認。** iOS Safari／Android Chrome の実機（アドレスバーの伸縮、セーフエリア、タップの感触、SVG の描画）では確認していない。確認は Chromium のみ。
2. **オートの止まり方（§3-1）と、紋章の置き換え（§3-4）は、意向の確認が要る。**
3. **オートの待ち時間は仮の値**（ふつう＝1.2 秒＋1 文字 0.08 秒）。実際に読んでの調整はしていない。
4. **横向きスマホの標準文字サイズ**（667×375 など）では、最長のページが 2 行のウィンドウに収まらず、ウィンドウ内スクロールになる。今回より前からの挙動で、変更していない。大・特大は 3 行にして収めた。
5. **「動きを減らす」設定の環境**では、4 結末後もタイトルの花びらは留まったまま、針も動かない（落ちる花びらが見えなくなるのを避けた）。その環境向けの「クリア後の印」は用意していない。
6. **読み上げ（スクリーンリーダー）での確認はしていない。** ボタンにはラベルを付け、オートには `aria-pressed` を付けたが、実際の読み上げは未確認。
7. **調査報告の時点で未解決だった、外部資料の一次確認**は今回も行っていない（実装の範囲外）。
8. 既読データは最大で 161 要素（シーン 20＋固有の段落 98＋選択肢 43）に増える。容量は 3KB 前後で、問題になる大きさではない。
