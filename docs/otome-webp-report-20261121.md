## 3. 変換方式とその理由

- 方式：Pillow 10.2.0（libwebp）で `lossless=True, quality=100, method=6`（ロスレスで、圧縮に最も時間をかけて小さくする設定）。`cwebp` は VM に入っていないため Pillow を使った。外部サービス・GPU は使っていない。
- 理由：
  - 線画（髪の細い線）と、縁のなじませ（半透明の画素）を持つ素材なので、劣化が「目視で分からない」ではなく「原理的に起きない」ロスレスを選んだ。
  - 非可逆（lossy）の WebP は色を間引いて保存する（色差 4:2:0）ため、細い線や赤いネクタイの縞の縁に色のにじみが出やすい。試算では q92・アルファはロスレスで合計 1,180,346 B（PNG の 12.8%）まで減るが、画質の保証が弱くなるため採らなかった（§6 に記載）。
  - 変換スクリプトは一時の場所（`/tmp/ahk-webp/convert.py`）に置き、リポジトリには入れていない。
- 補足：`exact` は指定していない。そのため **完全に透明（不透明度 0）の画素の色の値** は libwebp が圧縮しやすい値に変えることがある。完全に透明な画素は画面に出ないので見た目には影響しない（下の照合で、不透明度 0 の画素を除いて一致を確認）。

## 6. 判断に迷った点

- **ロスレスか、高画質の非可逆か**：非可逆（q92）なら合計約 1.18 MB（PNG の約 13%）まで減るが、線画と縞柄に色のにじみが出うるので、依頼の「劣化が目視で分からない」を確実に満たすロスレスを選んだ（約 4.3 MiB）。さらに軽くしたい場合は、非可逆版を作って同じ方法（濃紺合成＋拡大）で目視比較してから決めるのがよいと考える。
- **`cutout.py` の出力は PNG のまま**：透過済み PNG の再生成手順（`works/ano-hi-no-koe/tools/cutout.py`）は今回変えていない。今後立ち絵を作り直すときは「`cutout.py` で PNG を出す → WebP（ロスレス）に変換 → PNG を消す」の 2 段になる。手順の変更は依頼の範囲外と判断し、ツールとその説明文には触れなかった。
