- **本作の見た目と文言は 3.0-p3 と同じ**：旧版と新版の画面 164 枚を 1 画素ずつ比べて完全一致、文言 164 件も一致。
- `js/story.js` は 1 文字も変更していない（`tools/verify-text.js` は基準と完全一致）。localStorage のキー名は 5 件のまま。
- 既存の検査 5 本と、今回足した検査はすべて合格（§8）。
- 版表記は **3.0-p4** を提案し、ブランチにはその値を入れてある（理由は §6-1）。
- **マスターの判断が要るもの**：見送り候補のうち優先度「高」の 2 件（状態の変数の汎用化、選択肢なしのシーン遷移。§4-2）と、版表記（§6-1）。

## 1. 実施した汎用化と設計判断

### 1-1. 立ち絵 3 人の同時表示

| 内容 | 設計判断 |
| --- | --- |
| 位置は 1 か所に 1 人（左／中央／右）。同時に並ぶのは最大 3 人 | 「3 人まで」を別の上限として持たず、「位置が重ならない」という 1 つの規則から導いた。どの順で出し入れしても 3 人を超えず、重ならない（乱数で作った 300 通りの出し入れで確認） |
| `pos` を省いて新しく出た人は、空いている位置に立つ（中央 → 左 → 右） | 1 人目は中央なので、本作（1 人だけ）は従来とまったく同じ結果になる。従来は 2 人目も中央に重なっていた |
| 人のいる位置へ別の人が立つ・移ると、先にいた人が退場する | 4 人目を「エラー」にせず、書いた人の最後の指定を優先した。意図しない押し出しは点検ツールが「注意」として知らせる（§1-4） |
| 話者は手前（重なり順）に出し、1.04 倍に。話者でない人は明るさ 0.6（従来の値） | 強調と拡大は 2 人以上のときだけ。**1 人のときは何も変えない**（本作の表示を変えないため） |
| 地の文と、舞台にいない人の台詞では、全員同じ明るさ | 従来の挙動を引き継いだ |
| 2 人以上が同時に話す | `cast` の話者に `charas`（人物 ID の配列）を書く。舞台状態に `speakerCharas` を足した（従来の `speakerChara` は残してある） |
| 人物ごとの背丈 | `assets/manifest.json` の `characters[人物].scale`（省略＝1） |
| スマホ縦（幅 560px 以下）の 3 人 | 75% に縮め、左右を画面の端（15%／85%）へ寄せ、少し持ち上げる。端の人は体の外側が少し切れる。**縮めるだけだと顔がメッセージウィンドウの裏へ沈む**ため、持ち上げを足した（360×640・文字「特大」でも顔がウィンドウの上に出ることを検査） |
| それ以外（横向き・タブレット・PC）の 2〜3 人 | 横幅に収まる背丈までに抑える（PC では 1 人のときと同じ大きさ） |
| スマホ縦の 2 人 | 従来の指定（75%・32%／68%）のまま |

舞台指示の形式（`show`・`hide`・`chara`・`pos`・`speaker`）は従来のまま。足したのは `cast[話者].charas` と manifest の `scale` だけで、どちらも書かなければ何も起きない。

### 1-2. 長編の規模

検証データは `tools/fixtures/long/gen.js` が生成する（40 章 × 20 シーン＋結末 2。リポジトリには生成結果を置かない）。

| 観点 | 判断と対応 |
| --- | --- |
| **章立て** | `GameStage.addChapter(STORY, { id, title, scenes })` を足した。章ごとにファイルを分け、`index.html` に `<script>` を並べる。章のあるシーンでは、幕の呼び名が章の題名になる（「第 n 幕」の代わり。セーブの説明と「つづきから」も同じ）。本作は章を使わないので「第 n 幕」のまま |
| **遅延読み込みの要否** | **不要と判断し、実装していない。** 40 倍の物語データ（844 KB、章 40 ファイル）を起動時にすべて読んでも、処理を 4 倍遅くした環境でタイトル表示まで約 0.3 秒だった（手元のサーバでの値。通信の時間は含まない）。本作の密度（舞台指示が多い）で 40 倍にすると約 1.6 MB、圧縮して送れば 0.4 MB 前後の見込みで、立ち絵 1 枚（約 0.42 MB）と同じ程度。画像はもともとシーンごとに読んでいる。一方、遅延読み込みを入れると、選択・ロード・巻き戻し・セーブの妥当性判定がすべて「読み込み待ち」を挟む形になり、本作の進行の核に手が入る。得るものに対して危険が大きい |
| **既読データの肥大化** | 形式は変えていない（同じ配列）。変えたのは扱い方：従来はページを送るたびに全体を読み直し、線形に探し、シーンに入るたびに全要素を走査していた。保存されている文字列が前回と同じなら、ほどいた結果を使い回す形にした（別のタブや旧版が書き換えれば文字列が変わるので、自動で読み直す）。40 倍で全部読んだ状態は 6,167 要素・93 KB（localStorage の目安 5 MB の 3.6%）。既読のページを読み直しても書き込みは 0 回 |
| **セーブ／バックログ** | バックログはセーブデータに入るので、行数だけの上限（150 行）では、1 シーンが長い作品やフラグの多い作品で 1 件が際限なく太る。**ページ数（600）**と、**巻き戻し用の控え（フラグの写し）を持つ選択肢の数（40）**の上限を足した。超えたぶんは古い方から落ちる（控えだけが落ちた行は、文面は残り「戻る」が出なくなる）。本作は 1 周 20 シーン未満・100 ページ未満なので、どの上限にも届かない。既定の上限で 45 シーン進めたセーブは 19 KB だった |
| スロット数 | 作品設定で変えられる（既定 3）。本作は 3 のまま |

### 1-3. エンジンと作品の分離

- **`js/work.js`（新規）**：作品 ID、題名、タイトル画面の文言、HUD の用語、スロット数。エンジンはここから読む。
- **保存キー**：`作品 ID ＋ 役割`（`chrono-tale` ＋ `-save-v1` など）で組み立てる。本作のキー名は従来と同じ 5 件。同じサイトに別作品を置いても混ざらない。
- **作品設定を読めないとき**：ゲームを始めず、再読み込みの案内を出す。保存キーは 1 つも作らない（別の名前のキーで始めてしまい、セーブが消えたように見えるのを避けた）。
- **`css/work.css`（新規）**：シーンのテーマ色（`body.theme-xxx`）を `css/style.css` から移した。
- **HUD**：欠片・好感度それぞれ、呼び名を変える・隠すことができる。
- エンジンの文言に残っていた本作の用語（「時の欠片」「女神の心」）は作品設定へ移した。

### 1-4. 道具

- **`tools/validate-story.js`（新規）**：物語データの点検。どの作品にも使える。行き先の無い選択肢、`cast` に無い話者、manifest に無い背景・人物・表情、意図しない押し出しなどを拾う。本作は誤り 0 件・注意 0 件。
- **`tools/preview-server.js`**：`--work <フォルダ>` で、作品の差し替え分をエンジンに重ねて動かせる。
- **`tools/fixtures/trio/`（新規）**：3 人表示の検証用の「別作品」。持っているのは `work.js`・`story.js`・`manifest.json` の 3 ファイルだけで、エンジンと画像は本体のものを使う。人物 1 人は本作の立ち絵の流用、残りはサーバがその場で作る単純な図形（画像ファイルは足していない）。

## 3. スキル化への持ち出し手順

1. **コピーする（エンジン）**：`index.html`、`css/style.css`、`js/stage.js`、`js/assets.js`、`js/game.js`、`tools/preview-server.js`、`tools/validate-story.js`、`tools/lib/`。
2. **新しく書く（作品）**：`js/work.js`、`js/story.js`、`css/work.css`、`assets/manifest.json`、`assets/`。ひな形には `tools/fixtures/trio/` が使える。
3. `js/work.js`：`id` を決める（ほかの作品と重ならない名前。公開後は変えない）。題名・紹介文・HUD の用語・スロット数を書く。
4. `js/story.js`：`start`、`cast`、`scenes`、`maxShards`（使わなければ 0）、`maxAffection`、`endingCount`。
5. `assets/manifest.json`：`title`、`backgrounds`、`characters`。光輪を使わない人物には `halo` を書かない。
6. `css/work.css`：使うテーマの配色を書く。
7. `index.html` の書き換え：`<meta name="description">`、`theme-color`、`<title>`、タイトル画面の紋章。長編なら章のファイルの `<script>` を足す。部品の id は変えない。
8. 版：`index.html` の `data-app-version`・`?v=`（7 か所）と `js/game.js` の `VERSION` を、その作品の版にそろえる。
9. 点検：`node tools/validate-story.js` で誤り 0 件にする。`node tools/preview-server.js --placeholders` で、素材が届く前でも画面を確かめられる。

スキルにするときに足りないもの：§2 の 1〜6（とくに 1 と 3）、エンジンと作品でフォルダが分かれていないこと（§4-2 の 3）、別作品用の画面検査が無いこと（`tools/e2e-p4.js` の 3 人・長編の節が土台になる）。

## 5. 見送った汎用化と理由

- **シーン単位の遅延読み込み**：不要と判断（§1-2）。
- **既読形式の変更**：互換を保つ指示に従い、形式は変えずに扱い方だけを直した。
- **4 人以上の同時表示、左右の中間の位置**：要件は 3 人・3 位置。スマホ縦では 3 人が上限に近い（360px 幅で、隣どうしの中心の間隔が立ち絵の幅の約半分）。
- **人物ごとの減光・強調の切り替え指定**（ページ単位で「この人は暗くしない」など）：指定の形式を増やすほどの必要が見えなかった。話者による自動の切り替えだけにした。
- **立ち絵の移動の演出**（横から入る、入れ替わる）：位置の変更は従来どおり 0.5 秒で滑る。新しい演出は足していない。
- **本作の物語データへの章の導入**：本作のデータは増やさない・変えない方針のため、章は検証データでだけ使った。

## 6. 判断に迷った点

1. **版表記。** 指示は「報告書で提案」だが、ブランチには **3.0-p4** を入れた。`index.html` に読み込むファイルが 2 つ増えた（`js/work.js`・`css/work.css`）ため、版（`?v=`）を据え置くと、利用者の端末に残った古い `index.html` や古い `js`・`css` と新しいファイルが混ざり、古い画面の検出も働かない。マージできる状態にするには版を上げる必要があると考えた。別の表記にする場合は、`index.html`（`data-app-version`、`?v=` 7 か所、表記 2 か所）、`js/game.js` の `VERSION`、`tools/e2e-p3.js`・`tools/e2e-phase2.js` の期待値、README を置き換える。
2. **既存の検査の期待値を 3 か所書き換えた。** いずれも仕様の変更に合わせたもので、確認の数は減らしていない。
   - `tools/e2e-p3.js`・`tools/e2e-phase2.js`：版表記の期待値（3.0-p4）。
   - `tools/e2e-p3.js`：`?v=` の数（5 → 7）。
   - `tools/e2e-p3.js`：「`game.js` にキー名が 5 件書いてある」という照合を、「作品 ID ＋ `game.js` の語尾で組み立てた結果が既存 5 件と同じ」に変えた。実際に作られるキーが 5 件であることは、同じ検査の後ろの節と `tools/e2e-p4.js` が画面を動かして確かめている。
3. **4 人目の扱い。** 「誤りとして止める」「無視する」「先にいた人を退場させる」のうち、3 つ目にした。物語を書く側の最後の指定が画面に出るほうが分かりやすく、進行も止まらない。意図しない押し出しは点検ツールの注意で拾う。
4. **`pos` を省いた 2 人目の位置。** 従来は 2 人目も中央で、1 人目に重なっていた。空いている位置（左）に立つように変えた。本作には 2 人が並ぶ場面が無いので影響しない。
5. **話者の拡大（1.04 倍）。** 暗くするだけでも話者は分かる。スマホ縦の 3 人は重なるので、手前に出すだけでなく少し大きくしたほうが読み取りやすいと判断した。好みが分かれる所なので、値は `css/style.css` の 1 か所で変えられる。「動きを減らす」設定では拡大しない。
6. **スマホ縦の 3 人の並べ方。** 「縮めて全員を収める」と顔がメッセージウィンドウの裏へ沈み、「縮めない」と重なりが大きい。75% に縮め、左右を端へ寄せ、12% 持ち上げる形にした。持ち上げたぶん、立ち絵の下端（足もと）がウィンドウの中に来る。ウィンドウの濃さが「うすい」のときは足もとが透けて見える。
7. **HUD の「心」の文字を `<span>` で包んだ。** 作品設定から呼び名を入れるため。見た目は旧版と 1 画素も違わないことを確かめた。
8. **`css/work.css` へ移した星空の指定に `:not(.has-bg)` を足した。** もとは `css/style.css` の中の順番で「背景画像があるときは星空を出さない」が勝っていた。別ファイルへ移すと順番が逆になるため、同じ結果になるよう条件を書き足した。
9. **調査報告が `main` に無かった。** 指定のパスには無く、調査用ブランチにあったものを読んだ。`main` へは入れていない。
