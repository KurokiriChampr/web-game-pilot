# GUI・機能アップデートに向けた調査と提案（2026-11-16）

- 対象：`main`（ver 3.0-p2、Phase 1・2 完了時点）
- 範囲：調査と提案のみ。コードは変更していない（追加はこの報告書 1 ファイル）
- 依頼者：ベル（承認：マスター）

## 0. 要約

本作は **全 20 シーン・81 ページ・本文約 3,800 字、1 周およそ 10 分、結末 4 種** の短編である（`js/story.js` を実測）。したがって伸ばすべきは「長編を快適に読む機能」ではなく、**「短い物語を何度か読み直して 4 つの結末にたどり着く」体験** と、**スマホ縦画面での片手操作** の 2 点だと判断した。

推奨の上位 3 つ：

1. **読み返し・やり直しの導線**（バックログの不具合是正＋「この選択肢に戻る」＋エンディングからの復帰）
2. **下部クイックバーへの操作集約**（ログ／オート／スキップ／セーブ／メニューを親指の届く位置へ。絵文字アイコンを SVG＋文字ラベルに統一）
3. **既読をページ単位に**（条件付きの未読段落を飛ばさないスキップ、選んだことのある選択肢の印）

フローチャートからのジャンプ、シーン回想、実績、スワイプ操作、効果音などは見送りを推奨する（§5）。

## 2. 本作の現状（GUI／機能）の整理

コード（`index.html`、`js/game.js`、`js/story.js`、`css/style.css`、`assets/manifest.json`）の読解と、ローカルで起動した画面（390×844 の縦、1280×720 の横）の確認による。

### 規模

- 20 シーン（本編 13＋寄り道 3＋結末 4）、合計 81 ページ・約 3,800 字。1 シーンは 3〜7 ページ、1 ページは最長 81 字。
- 20 シーン中 11 シーンは、フラグや好感度で段落が増減する（`text` が関数）。
- 画像は背景 21 点＋立ち絵 12 点。**BGM ファイルは 1 つも無い**（`assets/bgm/` は空）。

### 機能の有無

| 観点 | 現状 |
| --- | --- |
| タイトル | キービジュアル全面＋ロゴ＋はじめから／つづきから／ロード／設定。結末 4 種の発見状況と読んだシーン数を表示 |
| テキストウィンドウ | 下部の半透明グラデーション。話者の名前札、幕とシーン名、ページ数（4 / 5）、▼。1 段落＝1 ページ |
| 選択肢 | 画面中央のオーバーレイ。番号付き、表示直後 0.45 秒は誤タップ防止。数字キー対応 |
| バックログ | あり（本文と選んだ選択肢、話者名つき）。閲覧のみ。セーブデータに含まれる |
| セーブ／ロード | オートセーブ（シーン単位）＋手動 3 スロット。文字だけの一覧。確認はブラウザ標準の `confirm` |
| 設定 | 文字速度 4 段階、既読シーンの瞬間表示、BGM 音量・ミュート、画像表示、揺れ・フラッシュ |
| スキップ | 既読シーンでのみ「⏭ スキップ」が出て、そのシーンの最終ページへ飛ぶ |
| オート | **無い** |
| 既読管理 | **シーン単位**（`chrono-tale-read-v1` にシーン ID の配列） |
| フローチャート／シーン回想／ギャラリー／実績 | 無い（結末一覧と「背景を見る」のみ） |

### 確認した問題点

1. **バックログに未読の段落が出る。** シーンに入った時点でそのシーンの全段落をログへ積むため（`logScene`）、4 / 5 ページ目を読んでいる最中にバックログを開くと 5 ページ目の本文が読めてしまう（画面で確認）。
2. **既読スキップが未読を飛ばしうる。** 既読はシーン単位だが、11 シーンは周回ごとに段落が変わる。2 周目で初めて出る条件付き段落（寄り道の成果など、周回の見どころ）もスキップ対象になる。
3. **縦画面で操作ボタンが遠い。** バックログ・ミュート・メニューは画面最上部の HUD、読み進めのタップは最下部。スキップボタンは名前札の行にある小さな文字（0.75rem）。
4. **やり直しが重い。** 別の結末を見るには、最初から読み直すか、事前に手動セーブしておくしかない。BAD END から直前の選択へ戻る手段が無い。
5. **死んでいる操作がある。** BGM が無いのに、HUD の一等地に 🔊 ボタン、設定に音量とミュートがある。
6. **タイトルの重なり。** 縦画面で、ロゴと紹介文がキービジュアルの顔に重なっている。
7. **見た目の不統一。** 操作アイコンが絵文字（📖🔊💾📂🏠）で、端末ごとに絵柄が変わり、金線基調の画面から浮く。確認ダイアログだけブラウザ標準の見た目になる。
8. 縦画面の HUD は「◇◇◇」と 💗 ゲージにラベルが無く、初見では意味が分かりにくい。

## 3. 提案する改善（GUI／機能）

コストは 小＝1〜2 ファイルの局所変更／中＝複数ファイル＋検査の追加／大＝新しい画面と新しいデータ構造、の 3 段階の見立て。全項目に共通する注意は §3 末尾にまとめた。

### A. 読み返し・やり直しの導線【機能・最優先】

- **内容**
  1. バックログの是正：現在のシーンは「読んだページまで」だけを表示する（表示側の変更のみ。保存形式は変えない）。
  2. 「この選択肢に戻る」：バックログの選択肢の行にボタンを置き、その選択の直前へ戻す。選択時に状態の控え（シーン・好感度・欠片・フラグ・幕数）をログの選択肢の行に持たせる。
  3. エンディング画面に「最後の選択肢からやり直す」を追加（2 と同じ仕組み）。
- **狙い・効果**：10 分の物語で結末が 4 つあるので、読み直しの軽さが満足度を決める。BAD END 直後に 1 タップで分岐点へ戻れる。手動セーブを「分岐前の保険」として使う必要が薄れる。1 は既存の不具合の解消。
- **コスト**：中（`game.js` と `index.html`／`css`、検査の追加）。
- **リスク**：控えはセーブデータへの項目追加になる（キーは不変、旧データは控えが無いだけで読める。旧データの行には「戻る」を出さない）。戻れることで選択の重みが薄れる懸念がある（§6）。

### B. 下部クイックバーと操作の整理【GUI・優先】

- **内容**
  1. テキストウィンドウの直下（または下端）に、ログ／オート／スキップ／セーブ／メニューの 5 つを横一列で置く。タップ領域は 44px 以上、読み進めのタップ領域とは線で区切る。
  2. アイコンを絵文字からインライン SVG＋短い文字ラベルに統一。押下時とオン状態（オート中・スキップ可）を明示する。
  3. 上部 HUD は状態表示（欠片・女神の心）に絞る。タップで「時の欠片 1 / 3」などの説明を出す。🔊 は設定の中へ移す。
  4. **オートモード**を追加：文字送り完了後、文字数に応じた待ち時間で次ページへ。速度は 3 段階。選択肢・ダイアログ表示・タブ非表示で止まる。
  5. 確認ダイアログを自前のモーダルに置き換える（`confirm` 5 か所）。
- **狙い・効果**：縦画面の片手操作で、よく使う操作が親指の範囲に入る。画面の統一感が上がる。オートは今回調べた資料の全てが「最低限」に挙げる機能で、本作に唯一欠けている。
- **コスト**：中（HTML・CSS・JS。`ELEMENT_IDS` による版ずれ検出の一覧も更新が要る）。オート単体は小。
- **リスク**：読み進めのタップとの押し間違い。ウィンドウ周りの高さが増え、立ち絵や選択肢の見える範囲が減る（小さい端末 360×640 相当での確認が必須）。オートは本作の短さとボイス無しでは効果が限定的（§6）。

### C. 既読をページ単位に【機能・優先】

- **内容**
  1. 既読を「シーン＋段落本文のハッシュ」で記録し、スキップは **未読ページの手前で止まる** ようにする。スキップボタンは既読ページがあるときだけ出す。
  2. 選んだことのある選択肢に小さな印（✓）を付ける。
  3. 記録は既存の `chrono-tale-read-v1` の配列に、シーン ID とは別形式の要素（例 `meet#a1b2`、`meet>0`）として追記する。
- **狙い・効果**：周回の見どころ（条件付きの段落）を飛ばさなくなる。「どれを選んだか」を覚えておく負担が消え、4 つの結末探しが進めやすくなる。
- **コスト**：中（`game.js` 中心）。
- **リスク**：既存キーの中身を拡張する案である。現行コードは未知の要素を無視する（`readScenes` がシーン ID だけを数える）ため旧版と共存でき、「読んだシーン n / 20」も変わらないが、「キーは変えない」の解釈に関わるので判断を仰ぎたい（§6）。印を付けすぎると攻略の手がかりになりすぎるので、条件で出現する選択肢に「NEW」は付けない。

### D. 読みやすさの設定【GUI】

- **内容**：文字サイズ 3 段階（標準／大／特大）、ウィンドウの濃さ（背景の見え方）を追加。設定画面に、実際の見え方が分かる例文プレビューを置く。BGM 関連は BGM が無い間は隠すか、1 か所にまとめる。
- **狙い・効果**：スマホでの読みやすさを利用者側で合わせられる。背景と立ち絵が売りなので、濃さを選べる価値がある。
- **コスト**：小〜中。
- **リスク**：特大では 81 字のページが 3 行に収まらない。ウィンドウ内スクロールにするか、高さを伸ばすかの設計が要る。設定項目は既存の `settings` キーへの追加で済む。

### E. セーブ／ロード画面【GUI】

- **内容**：各行に、そのシーンの背景画像（既存素材）の小さなサムネイル、幕とシーン名、欠片、日時を表示。ロード画面と同じ行構成でオートセーブも見せる。スロット数は 3 のまま。
- **狙い・効果**：どのデータがどこかを一目で判別できる。A が入れば手動スロットの出番は減るので、数は増やさない。
- **コスト**：小（サムネイルは `manifest.json` の画像を CSS 背景で使う）。
- **リスク**：画像の無いシーンではテーマ色の地にする等のフォールバックが要る。

### F. タイトルと「旅の記録」【GUI】

- **内容**
  1. 縦画面でロゴが顔に重ならないよう、ロゴの位置・大きさ、またはキービジュアルの焦点（`positionPortrait`）を調整する。
  2. 「つづきから」に、再開位置（第 n 幕「シーン名」）を添える。
  3. 結末一覧をタイトルから「記録」画面へ移し、見つけた結末は既存の結末画像のカードで見せる（未発見は伏せる）。
  4. TRUE END を見たあとは、タイトルの止まった花びらを「落ちる花びら」（既存の `petals-fall`）に変え、文字盤の針を動かす。
- **狙い・効果**：第一印象の改善。4 は「止まった世界の時間を動かす」という主題を、新規素材なしでタイトルに返す仕掛けで、クリアの手応えになる。
- **コスト**：1・2・4 は小、3 は中。
- **リスク**：4 は演出の解釈に関わるので、マスターの意向確認が要る（§6）。

### G. 道のりチャート（閲覧のみ）【機能・次点】

- **内容**：「記録」画面に、20 シーンを縦に並べた簡易チャート（SVG）を置く。読んだシーンは名前を、未読は「？」を表示。**ジャンプ機能は付けない。**
- **狙い・効果**：寄り道 3 つと結末 4 つの取りこぼしが見える。縦画面と縦に流れる図は相性が良い。既存の既読データだけで作れる。
- **コスト**：中（配置の定義と SVG 描画）。
- **リスク**：分岐構造そのものがネタバレになる（特に 4 つ目の結末の存在位置）。1 つ目の結末を見るまで非表示にする等の配慮が要る。

### 全項目に共通する注意

- `story.js` の本文・分岐条件・effects には触れない。`tools/verify-text.js` と基準データで本文不変を照合できる。
- localStorage は既存 5 キーのまま（`tools/e2e-phase2.js` に「既存 5 件以外のキーを作らない」検査がある）。A・C・D はいずれも既存キー内への項目追加で設計した。
- 画面部品を足すたびに、`game.js` の `ELEMENT_IDS` と版表記（`index.html` の `data-app-version`・`?v=`、`game.js` の `VERSION`）をそろえる必要がある。
- `tools/e2e.js`（Phase 1 の検査）は Phase 2 報告の時点で既に通らない状態と記録されている。GUI を変える前に検査の土台を直すと、以後の確認が楽になる。

## 4. 優先順位の推奨

| 順 | 項目 | 理由 |
| --- | --- | --- |
| 1 | **A. 読み返し・やり直しの導線** | 本作の遊びの中心は「短い物語を読み直して別の結末へ」。そこが現状いちばん重い。未読がバックログに出る不具合の解消も含む。調査した分岐作品（The Hundred Line、パラノマサイト、学マスの巻き戻し、Ren'Py のロールバック）が共通して手当てしている箇所でもある |
| 2 | **B. 下部クイックバーと操作の整理** | スマホ縦が第一対象なのに、操作が画面の上端に集まっている。見た目の統一（アイコン、確認ダイアログ）も同時に片付き、完成度の印象が最も変わる。A の「ログから戻る」を使いやすくする土台にもなる |
| 3 | **C. 既読をページ単位に** | 周回して初めて出る段落を既読スキップが飛ばす、という現状は、分岐を作り込んだ本作の良さを自分で隠している。A・B と合わせて「2 周目以降」が完成する |

次点は D（文字サイズ）→ F の 1・2・4（タイトルの小改善）→ E（セーブ画面）→ G（道のりチャート）→ F の 3（記録画面）の順。D と F の小改善はコストが小さいので、上位 3 つと同じ回に入れてもよい。

## 5. 見送るべき候補と、その理由

| 候補 | 理由 |
| --- | --- |
| フローチャートからのジャンプ | 任意のシーンへ飛ぶには、その地点の好感度・フラグの控えを周回をまたいで保存する必要があり、新しいデータ構造が要る。20 シーンの規模なら A の「選択肢に戻る」で足りる |
| シーン回想 | 11 シーンは状態で本文が変わるため、「どの状態で再生するか」を決められない。1 周 10 分なので読み直す方が早い |
| 実績 | 結末 4 種と読んだシーン数が、すでに実績の役を果たしている。項目を足しても水増しになる |
| CG ギャラリー | F の結末カードと既存の「背景を見る」で足りる。独立した画面を作るほどの点数（21 点）が無い |
| クイックセーブ／クイックロード、スロット増設 | シーンごとのオートセーブと A の巻き戻しで用が足りる |
| スワイプ・長押しなどのジェスチャー | スマホでは意図しない入力になりやすい（さくた氏の記事）。ブラウザでは「戻る」スワイプや引っ張って更新とも衝突する |
| 効果音、ボイス、音量の細分化 | 音の素材が 1 つも無い。BGM の有無が決まってから考える |
| 未読も含む強制スキップ、選択肢後もスキップ継続 | 1 シーン 3〜7 ページなので、シーンごとの既読スキップで十分に速い。未読を飛ばす手段は本作では害が大きい |
| チャット風など画面構成の作り替え | 立ち絵と背景を見せる現在の構成が本作の素材に合っている |
| PWA 化（オフライン対応） | キャッシュの仕組みが、既存の「古い画面の検出と読み込み直し」と干渉しうる。全画面表示だけが目的なら別途、小さく検討できる |
| 振動フィードバック | iOS の Safari で使えず、第一対象の半分に届かない |

## 6. 判断に迷った点

1. **「この選択肢に戻る」を常時使えるようにするか。** 初回から使えると BAD END の重みは薄れる。一方、10 分の短編で「最初からやり直し」を強いる方が離脱を招くと考え、常時利用可を推奨した。「1 つ目の結末を見てから解放」という中間案もある。
2. **既読データの拡張（C）は制約の範囲内か。** キー名は変えず、旧版が無視する形の追記にしたが、「既存キーの中身に新しい種類の値を入れる」ことをどこまで許すかは、依頼側の判断に委ねたい。認められない場合、C はページ単位の既読を保存せず「その周回で読んだ分だけ」に縮めるか、見送る。
3. **オートの優先度。** どの資料も最低限の機能に挙げるが、本作は短く、ボイスも無く、スマホでは手が画面にある。単体の効果は小さいと見て、独立項目にせず B に含めた。
4. **道のりチャートを上位に入れるか。** 縦画面との相性は良く、既存データで作れる。しかし分岐構造の開示は発見の楽しみを削る面があり、A・C が入れば取りこぼしは別の形で減るため、次点にとどめた。
5. **好感度ゲージを見せ続けるか。** 常時表示は「正解探し」を促す面がある。今回は現状維持とし、提案に含めていない。
6. **結末後のヒント表示。** README にあるヒントをゲーム内（結末画面）にも出すと親切だが、新しい文章を書くことになる。本文には触れないが、文章の追加はマスターの領分と考え、提案から外した。
