## 3. 実装の中身

### 3.1 紋章

- 紋章の要素はエンジン共通の `index.html` にあるが、表示は CSS だけで消せるので、作品の `work.css` に `.title-emblem { display: none; }` を置いた。本編は自分の `css/work.css` を読むので影響しない。
- 縦画面では、紋章（64px）の下に紹介文を送る計算（`38dvh - 78px`）があった。紋章が無くなると紹介文が 64px 上がって題字に近づくので、`38dvh - 14px` に直し、**絵の上での紹介文の位置は変更前と同じ**にした。絵が読めなかったときの文字のロゴ（`.title-sub`）も同じ考え方で位置を合わせた。
- PC（横長）ではロゴの列が縦方向の中央寄せなので、紋章の分だけ紹介文が少し上がる（1366×768 で約 50px）。題字には重ならない（スクリーンショットで確認）。

### 3.2 進行状況

- 「進行状況」ボタンはメニューの最後（設定の下）。押すと「進行状況」のダイアログに、従来タイトル画面にあった「見つけたエンディング n / 14」「読んだシーン n / 45」がそのまま入る。閉じるボタン・枠の外・Esc で閉じる（既存のダイアログと同じ仕組み）。
- 一覧は、スマホ幅（560px 未満）では 1 列、PC では 2 列。従来は 1 行に収めるため結末名を「BAD END「借り…」と省略していたが、ダイアログでは省略せず折り返す。
- 背の低い画面（高さ 700px 以下）では行間を詰め、360×640 でもダイアログが画面に収まる。
- 360×640 などの背の低い縦画面は、従来メニューを 2 列にしている。ボタンが 1 つ増えて「進行状況」だけが半端に 1 個残るため、この作品ではロード・設定・進行状況を 1 行 3 列にした。

## 5. 判断に迷った点

1. **エンジンに手を入れたこと**：紋章は作品側の CSS だけで消せたが、「進行状況」ボタンはタイトル画面の HTML（エンジン共通の `index.html`）に要素が無いと置けない。作品側の CSS で一覧を隠すだけでは「ボタンで開く」が作れないため、依頼の条件どおり、作品ごとの設定（`WORK.titleProgress`）で切り替える形にした。既定は従来どおりで、本編の見た目は 1 バイトも変わらないことを確かめた。
2. **版（3.0-p4）を上げなかった**：`index.html`・`game.js`・`style.css` は変わったが、本編の遊び・見た目は変わらないので版はそのまま。ただし `?v=3.0-p4` のままなので、公開を更新したとき、ブラウザに古い `game.js`／`style.css` が残っていると、新しい `index.html` と組み合わさる可能性がある。その場合でも、古い `game.js` はボタンを `hidden` のまま無視するだけ（従来の一覧はタイトル画面に出たまま）で、壊れはしない。逆（新しい `game.js`＋古い `index.html`）はエンジンの既存の仕組み（要素がそろっていないと再読み込み）で処理される。公開の更新時に版を上げるかどうかは、マスター／ベルの判断に任せたい。
3. **ボタンの名前と位置**：依頼の文言どおり「進行状況」とし、メニューの最後に置いた。ダイアログの見出しも「進行状況」。中の見出し「見つけたエンディング」「読んだシーン」は従来の文言のまま。
4. **背の低い縦画面での 3 列**：360×640 では「ロード｜設定｜進行状況」を 1 行に並べるため、この作品のその画面に限りボタンの字間を従来の 0.2em から 0.1em に詰めた。
5. **PC で紹介文が少し上がる**：紋章の分だけロゴの列が縦に詰まり、紹介文が約 50px 上がる。スマホ縦は絵との位置関係を変えないよう計算を直したが、PC はロゴの列が中央寄せのため、そのままにした。
